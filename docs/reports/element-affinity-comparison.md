# Element-affinity comparison for #168

Generated by `python tools/analysis/compare_element_affinity.py` from the live
`data/elements.json` relationship graph and `data/engine.json::elementRules`.
This is a Phase-1 decision artifact. **It does not select or implement a new
combat formula.**

## Models under comparison

1. **Current** reproduces `engine/effects_core.lua`: skill and innate-user layers
   are separate; each layer adds diminishing strong bonuses, multiplies weak
   penalties, then the two layers multiply together.
2. **Signed net / separate** keeps the skill and innate-user layers separate,
   but computes `strong - weak` before converting each layer to a multiplier.
   One-sided matchups therefore retain the current curve while exact opposing
   relations cancel to exactly `1.0` inside that layer.
3. **Signed RMS / separate** also cancels relations before multiplier math, then
   divides each layer's signed score by `sqrt(pair_count)`. Repeated alignment
   still gains intensity, but large attacker/target cross-products grow more
   slowly and breadth has less numerical leverage.
4. **Weighted signed / joint** is the deliberately more radical comparison. It
   combines skill and innate relations into one signed score before applying the
   current skill curve. One innate relation is weighted at **0.272** of one
   skill relation, derived from the present first-step skill/user tuning. This
   tests whether "what you wield" and "who you are" should cancel before either
   becomes a multiplier. It is diagnostic, not a recommended constant.

`ELEMENT_RATE` traits are intentionally absent from these fixtures. They remain
an explicit separate modifier layer in #168.

## Reading labels

`neutral` means exactly `1.0`. `near-neutral` means a non-neutral value within
5% of `1.0`; this label exists specifically to expose the current readability
problem rather than hide it behind a coarse category.

### Immediate observations

- The current model's characteristic residue is visible in **RG -> Blue**,
  **RB -> Green**, and every **RGB -> R/G/B** case: a strong and weak relation
  multiply to `1.035` rather than cancelling.
- Signed-net makes those exact conflicts exactly neutral while preserving the
  current `R -> G`, `R -> B`, `RR -> G`, and `RR -> B` magnitudes.
- Signed-RMS also cancels cleanly, but deliberately weakens the meaning of raw
  element-count depth: `RR -> Green` is milder than under current/signed-net.
- The joint model is close to current mono-element innate tuning but changes it
  slightly because one common weight is used for positive and negative innate
  pressure on the skill curve.

- Cross-product multiplication causes several broad-vs-broad current results to
  hover near neutral without being neutral (`RG -> RGB`, `RGB -> RG`,

### Immediate observations

- The minimal signed-net model mostly changes **mixed innate composition**, not
  the established relative importance of the skill layer. That is useful if the
  intended fix is narrow.
- A broad RGB caster becomes exactly innate-neutral under signed models, so a
  favorable Red skill into Green reads as exactly the skill's `1.5x`, rather
  than current `1.552x` residue.
- The joint model changes agreement/conflict between skill and innate identity,
  which may be desirable if the two channels are meant to negotiate one final
  elemental verdict. It is also the largest conceptual departure and would
  require the clearest player-facing rule.

## Design trade-offs

| Model | Cancellation | Repeated-depth expression | Broad/mixed identity | Skill/user roles | Main risk |
|---|---|---|---|---|---|
| Current | No | Strong | Often leaves arithmetic residue | Very clear separate channels | Player cannot predict near-neutral leftovers |
| Signed net / separate | Exact inside each layer | Strong; same one-sided curve as current | Mixed colors cancel cleanly | Preserves current two-channel doctrine | Cross-product magnitude can still grow quickly |
| Signed RMS / separate | Exact inside each layer | Present but damped | Clean cancellation; breadth naturally moderates intensity | Preserves separate channels | The square-root normalization is harder to explain diegetically |
| Weighted signed / joint | Exact in the joint score | Present | Clean cancellation across innate and skill pressure | One final elemental verdict | Reweights established skill-vs-innate semantics; calibration becomes a new design surface |

## Decision gate

Before touching `engine/effects_core.lua`, choose the **shape** of the rule:

- **A — signed net / separate** if skills and innate identity should remain two
  independent channels and the main defect is multiplication residue;
- **B — signed RMS / separate** if A is conceptually right but raw element-count
  cross-products make repeated/broad compositions too explosive;
- **C — weighted signed / joint** if skill and innate relationships should
  negotiate one elemental result before multiplier conversion;
- or specify a fourth rule after inspecting the table.

Only after that choice should the numeric strong/weak values be recalibrated.
That keeps #168's aggregation decision separate from broad combat rebalance.
