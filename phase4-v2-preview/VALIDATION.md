# Phase 4 V2 Blender Validation

The canonical field is generated by `tools/asset-gen/surface_baselines_v2.py` and is hash-checked by the Blender builder before mesh creation. The builder creates inspection-only Blender meshes, `.blend` files, and renders; it does not write canonical PNGs.

The required source search for `ray_cast`, `BVHTree`, `scene.ray_cast`, `random.`, and `import random` returned no matches in the V2 generator or builder. No production PNG is used as a correction input. The Blender derivatives therefore remained derivative-only.

The canonical baseline set was regenerated with the repository-owned PNG serializer and passes `--runs 3 --verify`. All four preview meshes verify their recorded canonical field hash; the preview outputs remain derivatives and do not write canonical assets.

The builder required one narrowly scoped Blender 5.1 compatibility fix: `BLENDER_EEVEE_NEXT` was changed to the enum exposed by this installation, `BLENDER_EEVEE`. No recipe, field encoding, or hash logic changed.

The builder produced no OBJ or MTL files; mesh counts and bounds in `mesh-report.json` are from the generated 3×3 repeated or edge-padded Blender meshes represented in each `.blend`.
